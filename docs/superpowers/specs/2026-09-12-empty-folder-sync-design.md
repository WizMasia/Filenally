# Empty Folder Synchronization Design

## Goal

파일과 함께 디렉터리 존재 여부를 추적하여 빈 폴더를 안전하게 동기화한다. 양방향, 원본 → 대상, 대상 → 원본의 각 동기화 방향을 파일과 폴더에 동일하게 적용하고, 삭제 전파가 필요한 빈 폴더는 영구 삭제하지 않고 실행별 `.trash` 구조에 보존한다.

## Scope

- 모든 제외되지 않은 디렉터리의 상대 경로를 스캔한다.
- 폴더 쌍별 매니페스트에 양쪽 디렉터리 존재 여부를 기록한다.
- 신규 빈 폴더 생성, 기준선 저장, 신뢰된 삭제 전파를 계획한다.
- 폴더 생성은 부모부터, 폴더 삭제는 파일 작업 후 자식부터 실행한다.
- 폴더 삭제 직전에 실제로 비어 있는지 다시 검사한다.
- 빈 폴더 작업을 비교 결과와 상세 실행 로그에 표시한다.
- 단방향 파일 삭제 처리도 같은 권위 방향 규칙을 따르도록 수정한다.
- 기존 schema v2 상태와 JSON 백업을 안전하게 정규화한다.

## Direction Semantics

동기화 방향은 어느 쪽이 신규 상태와 삭제 상태의 권위 원본인지를 결정한다.

| 방향 | 원본에만 존재 | 대상에만 존재 |
|---|---|---|
| 양방향 | 과거 양쪽 존재 기록이 없으면 대상으로 생성한다. 과거 양쪽 존재 기록이 있으면 대상에서 삭제된 것으로 판단하여 원본 항목을 `.trash`로 보낸다. | 과거 양쪽 존재 기록이 없으면 원본으로 생성한다. 과거 양쪽 존재 기록이 있으면 원본에서 삭제된 것으로 판단하여 대상 항목을 `.trash`로 보낸다. |
| 원본 → 대상 | 대상으로 생성하거나 다시 생성한다. | 과거 양쪽 존재 기록이 있으면 원본의 삭제를 대상에 전파하여 대상 항목을 `.trash`로 보낸다. 이력이 없는 대상 전용 항목은 보호한다. |
| 대상 → 원본 | 과거 양쪽 존재 기록이 있으면 대상의 삭제를 원본에 전파하여 원본 항목을 `.trash`로 보낸다. 이력이 없는 원본 전용 항목은 보호한다. | 원본으로 생성하거나 다시 생성한다. |

위 규칙은 파일과 디렉터리에 동일하게 적용한다. 특히 단방향 동기화에서 비권위 쪽 사용자가 파일이나 빈 폴더를 삭제해도 권위 쪽 항목을 삭제하지 않고 다시 생성한다.

양방향 삭제 전파는 기존 파일 안전 규칙을 유지한다. 신뢰된 매니페스트가 없거나 이전에 양쪽 모두 존재했다는 기록이 없으면 삭제로 추론하지 않는다.

## Scan Model

`FileAdapter.scan()`은 다음 모양의 트리 스냅샷을 반환한다.

```js
{
    files: Map<string, FileEntry>,
    directories: Set<string>,
}
```

`directories`에는 루트 자체를 제외하고 모든 제외되지 않은 디렉터리의 상대 경로를 넣는다. 비어 있지 않은 디렉터리도 기록해야 중첩된 빈 폴더의 생성·삭제와 부모 존재 여부를 정확히 비교할 수 있다.

`.trash`와 정규화된 사용자 제외 경로는 현재와 동일하게 재귀 순회하지 않으며 디렉터리 집합에도 넣지 않는다. 제외된 자식만 가진 부모는 실제로 비어 있다고 간주하지 않는다. 폴더 삭제 실행 시 브라우저 파일시스템의 실제 엔트리를 다시 확인하므로 제외된 내용이나 비교 후 새로 생성된 내용이 있는 폴더는 제거하지 않는다.

## State and Compatibility

프로필에 선택적 `directoryManifest`를 추가한다.

```js
directoryManifest: {
    "reports/archive": { source: true, target: true }
}
```

경로별 값은 각 쪽에 디렉터리가 존재했는지만 나타낸다. 파일 매니페스트와 분리하여 기존 파일 스냅샷 형식과 플래너 로직의 변경 범위를 제한한다.

schema 버전은 2를 유지한다. `directoryManifest`가 없는 기존 상태는 빈 객체로 정규화한다. 이는 기존 프로필의 과거 디렉터리 상태를 알 수 없다는 뜻이며, 첫 비교에서 기존 폴더를 삭제 근거로 사용하지 않는다. 성공한 동기화 후 현재 양쪽 디렉터리 상태를 저장하면서 이후 비교부터 삭제 감지가 활성화된다.

JSON 복원 후 프로필을 다시 검증하기 전에는 기존 파일 매니페스트와 동일하게 디렉터리 매니페스트도 삭제 판단에 사용하지 않는다.

## Planning

`SyncPlanner.plan()`은 파일 Map 두 개와 디렉터리 Set 두 개를 함께 받는다. 디렉터리 계획에는 다음 작업 유형을 사용한다.

- `baseline-directory`: 양쪽에 이미 존재하지만 과거 디렉터리 기록이 없는 경로를 기준선으로 저장한다.
- `create-directory`: 방향 규칙에 따라 반대쪽에 디렉터리를 만든다.
- `trash-directory`: 신뢰된 삭제를 반대쪽에 전파한다.

이력이 없는 비권위 쪽 전용 디렉터리는 파일의 `protected` 상태와 동일하게 보호한다. 양쪽에 존재하는 디렉터리는 내용 유무와 무관하게 변경 작업이 필요 없다. 양쪽에서 모두 사라진 과거 경로는 다음 성공 매니페스트에서 자연스럽게 제거한다.

실행 계획은 다음 순서로 정렬한다.

1. `create-directory`: 경로 깊이 오름차순
2. 기존 파일 작업: 현재 플래너 순서 유지
3. `trash-directory`: 경로 깊이 내림차순

부모 디렉터리를 만드는 파일 복사 로직은 그대로 유지한다. 명시적 디렉터리 작업은 파일이 없어도 폴더 구조가 존재하도록 보장한다.

## File Direction Safety Fix

현재 파일 플래너는 과거 양쪽에 존재한 파일이 한쪽에만 남았을 때 단방향 권위를 확인하지 않고 남은 파일을 휴지통으로 보낼 수 있다. 디렉터리 규칙 도입과 함께 이 분기를 수정한다.

- 원본 → 대상에서 원본 파일만 남으면 대상으로 다시 복사한다.
- 원본 → 대상에서 대상 파일만 남고 신뢰된 양쪽 기록이 있으면 대상을 `.trash`로 보낸다.
- 대상 → 원본에서는 위 규칙을 반대로 적용한다.
- 양방향에서는 기존 삭제 감지 규칙을 유지한다.
- 이력이 없는 비권위 쪽 전용 파일은 기존처럼 보호한다.

이 변경은 새로운 기능이 아니라 단방향 동기화가 명시한 권위 방향을 지키기 위한 데이터 손실 방지 수정이다.

## Execution and Trash Safety

`FileAdapter.createDirectory()`는 `getDirectoryHandle(pathPart, { create: true })`를 순서대로 호출한다.

`FileAdapter.moveDirectoryToTrash()`는 다음 절차를 수행한다.

1. 안전한 상대 경로인지 검증한다.
2. 원래 디렉터리의 실제 엔트리를 열거한다.
3. 엔트리가 하나라도 있으면 `InvalidModificationError`로 중단한다.
4. `.trash/<run stamp>/<original path>` 디렉터리를 생성한다.
5. 원래 부모에서 `removeEntry(name)`을 호출한다.

자식부터 처리하기 때문에 전체 빈 디렉터리 트리를 삭제할 때 각 빈 폴더 경로가 동일한 실행별 `.trash` 트리에 보존된다. 파일이나 제외된 엔트리가 남아 있으면 원래 디렉터리는 제거되지 않으며 실행 로그에 실패가 기록된다.

브라우저 API에 이식 가능한 디렉터리 이동 지원이 없으므로 빈 디렉터리는 `.trash`에 같은 구조를 만든 뒤 원래 빈 디렉터리를 제거한다. 파일 내용이 없으므로 copy 작업은 필요하지 않다.

## UI and Detailed Logs

기존 양쪽 비교 테이블에 디렉터리 행을 함께 표시한다. 디렉터리는 경로 끝에 `/`를 표시하고 크기와 수정일은 `—`로 표시한다. 상태 배지와 변경된 항목만 보기 필터는 파일과 같은 렌더링 경로를 재사용한다.

상태 문구는 다음 작업을 한국어와 영어로 구분한다.

- 폴더 생성 / Create folder
- 폴더 기준선 / Save folder baseline
- 폴더를 휴지통으로 이동 / Move folder to trash
- 단방향 보호 / Protected by one-way mode

상세 실행 로그는 기존 작업 엔트리 형식을 유지하고 `action` 값에 `create-directory`, `baseline-directory`, `trash-directory`를 기록한다. CSV와 JSON 다운로드는 기존 일반 작업 내보내기 경로를 그대로 사용한다.

## Failure Handling

- 비교와 실행 사이에 폴더 내용이 바뀌면 삭제 직전 검사에서 실행을 중단한다.
- 디렉터리 생성이나 제거가 권한·운영체제·저장소 제공자 오류로 실패하면 이후 작업을 시작하지 않는다.
- 성공한 작업 수와 실패 작업은 기존 체크포인트 및 실행 로그에 기록한다.
- 실패하거나 중단된 실행 뒤에는 현재 파일·디렉터리를 다시 스캔하여 화면에 표시하지만, 사용자는 새 비교를 실행해야 한다.
- 매니페스트는 기존 정책대로 실행 후 실제 양쪽 상태를 다시 스캔하여 만든다. 실패·중단 로그 자체를 다음 상태 판단의 근거로 사용하지 않는다.

## Verification

브라우저 회귀 테스트는 다음 동작을 증명해야 한다.

1. 원본의 신규 빈 폴더가 원본 → 대상에서 대상에 생성된다.
2. 대상의 이력 없는 빈 폴더가 원본 → 대상에서 보호된다.
3. 원본에서 삭제된 동기화 완료 빈 폴더가 대상의 실행별 `.trash`에 보존된다.
4. 비권위 대상에서 삭제된 빈 폴더가 원본 → 대상에서 다시 생성된다.
5. 대상 → 원본은 위 두 단방향 규칙을 대칭적으로 적용한다.
6. 양방향은 어느 한쪽에서 삭제된 동기화 완료 빈 폴더를 반대쪽 `.trash`로 보낸다.
7. 여러 단계의 신규 빈 폴더는 부모부터 생성되고 삭제된 트리는 자식부터 제거된다.
8. 삭제 직전에 내용이 생긴 폴더는 제거되지 않고 실패 로그를 남긴다.
9. 제외 디렉터리와 그 내용은 폴더 계획에 포함되지 않는다.
10. 상세 이력과 CSV/JSON 내보내기에 폴더 작업 종류와 경로가 포함된다.
11. 원본 → 대상에서 비권위 대상 파일만 삭제되면 원본 파일을 대상으로 다시 복사한다.
12. 대상 → 원본에서 비권위 원본 파일만 삭제되면 대상 파일을 원본으로 다시 복사한다.
13. 기존 schema v2 데이터는 디렉터리 이력 부재를 삭제로 오인하지 않는다.

각 동작은 실패하는 테스트를 먼저 추가한 뒤 최소 구현으로 통과시킨다. 전체 `npm test`, 빌드 일치 검사, 375/768/1280 px 시각 검증을 완료한다.

## Non-Goals

- 백그라운드 파일시스템 감시나 자동 동기화를 추가하지 않는다.
- 빈 폴더를 표현하기 위한 `.gitkeep` 또는 기타 표시 파일을 만들지 않는다.
- 제외된 디렉터리 내부를 검사하거나 동기화하지 않는다.
- 비어 있지 않은 디렉터리를 재귀 옵션으로 한 번에 삭제하지 않는다.
- 디렉터리 생성일, 수정일, 소유자 또는 권한 메타데이터를 보존하지 않는다.
- schema 전체를 통합 파일·폴더 엔트리 모델로 재작성하지 않는다.
- #12의 일반 파일 버전 관리 기능을 함께 구현하지 않는다.
